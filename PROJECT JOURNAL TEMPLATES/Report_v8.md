## 1. Диагностика и первопричины сбоя Internal Server Error (500)

В ходе глубокого анализа логов компиляции Webpack и Dev-сервера Next.js были выявлены следующие причины сбоя:

1. **Кросс-дисковое разрешение модулей Webpack в Windows:**
   - Next.js при старте из глобального кэша `C:\Users\Lenovo\...` вычислял относительные пути (`path.relative`) до корня проекта на виртуальном Google Диске (`G:\Мой диск\Проект\FlightSaver`).
   - На Windows относительный путь между разными дисками `G:` и `C:` является абсолютным, из-за чего Webpack генерировал невалидный селектор `./C:/Users/...` и завершался ошибкой `Module not found: Can't resolve ./C:/Users/.../app-next-dev.js`.
2. **Неполнота файлов `styled-jsx` и PostCSS/шрифтов:**
   - Модули `styled-jsx` и PostCSS/Tailwind в `node_modules` были повреждены прерванными процессами распаковки `npm install` на виртуальном диске Google Drive (`createStyleRegistry is not a function`).
   - Загрузчик `next/font/google` в `app/layout.tsx` падал при попытке динамической загрузки Google Fonts без сетевого доступа в Webpack.

## 1. Обзор выполненных работ

В проекте FlightSaver реализован полнофункциональный серверный ИИ-парсер пользовательских поисковых и голосовых запросов на базе Google Gemini API (`app/api/search/route.ts`), интегрированный с интерфейсом главной страницы.

### Ключевые возможности:
1. **Серверный маршрут `app/api/search/route.ts`:**
   - Обработка POST- и GET-запросов с телом `{ query: string, currency?: string }`.
   - Использование серверной переменной окружения `process.env.GEMINI_API_KEY`.
   - Системный промпт для моделей Gemini 2.0 Flash / 1.5 Flash / 2.5 Flash / 3.x Flash с генерацией строго типизированного JSON:
     ```json
     {
       "origin": "IATA-код города вылета (например: UUS, MOW, LED)",
       "originName": "Название города вылета на русском (например: Южно-Сахалинск)",
       "destination": "IATA-код города прилета (например: CXR, BKK, DXB, HKT)",
       "destinationName": "Название города прилета на русском (например: Нячанг)",
       "departureDate": "YYYY-MM-DD или null",
       "returnDate": "YYYY-MM-DD или null",
       "passengers": 1,
       "cabinClass": "economy",
       "hasLuggage": false,
       "wantsStpcHotel": true,
       "maxBudget": null,
       "aiSummary": "Краткое дружелюбное пояснение на русском, что нашел и понял ИИ"
     }
     ```
   - **Отказоустойчивый резервный парсер (Dual-Layer Fallback):** При любых сетевых сбоях, лимитах или ошибках прав доступа API-ключа Gemini, обработчик автоматически и без задержек переключается на встроенный детерминированный ИИ-парсер `lib/nlpParser.ts`, выдающий аналогичную структуру и живое грамматически выверенное резюме `aiSummary`.

2. **Интеграция с главной страницей (`app/page.tsx`):**
   - Функция `handlePerformSearch` отправляет асинхронный POST-запрос на `/api/search`.
   - Поддерживает запуск поиска по нажатию Enter, кнопки со стрелкой «→», клику по быстрым подсказкам или повторному поиску из личного кабинета.
   - Во время выполнения запроса отображается анимированный статус:  
     *«ИИ Консьерж анализирует маршрут и подбирает лучшие тарифы...»*

3. **Отображение карточки параметров маршрута (`components/FlightResultsList.tsx`):**
   - В блоке ИИ-Консьержа выводится поясняющий текст `aiSummary`.
   - Отображаются стильные плашки с распознанными параметрами:
     - ✈️ Маршрут с IATA-кодами (например: `Москва [MOW] ➔ Нячанг [CXR]`)
     - 📅 Дата вылета и длительность (например: `ноябре (14 дн.)`)
     - 👥 Количество пассажиров
     - 🧳 Статус багажа
     - 🏨 Бесплатный 4★ отель STPC при стыковке
